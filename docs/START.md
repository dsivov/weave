We already created a weave project as a part of Conte_Graph project (see ../Context_Graph/README.md). Now we will create a new weave project, where weave will be first class citizen. This project will be called "Weave". The goal of this project is to create Multi User software that will allow multiple users to collaborate on the same project in real-time. Conte Graph will be used as a base for this project, but we will add new features and functionality to make it more suitable for multi-user collaboration. 
Our goals : 
1. Create a new weave project called "Weave" that is designed for multi-user collaboration.
2. Rebranding the existing Conte_Graph project to make it more suitable for multi-user collaboration (under his own git and layout, keeping original CG as generic product in its own directory).
3. Implement real-time collaboration features that allow multiple users to work on the same project simultaneously.
4. Re-think the architecture of the existing Conte_Graph project to make it more suitable for multi-user collaboration, especially in terms of configuration: add UI features to allow users to configure the project and its components in a more user-friendly way (relevant to Weave goals): For example, studio, rules, ontologies and other configuration options should be easily accessible and modifiable by Weave oriented wizards, with preloaded templates and option to change it but in scope of Weave functionality.
5. Full productisation of the Weave project, including documentation, testing, and deployment.
6. Make new Weave-based team onboarding essentially easier than onboarding to Context_Graph, by providing a more user-friendly interface and better documentation.
7. Solve the problem of multi-user collaboration in a way that is scalable and efficient, allowing for a large number of users to work on the same project without performance issues.
8. Solve the problem of developer role: make it autonomous as in current Context_Graph/Weave, but with option to control it from Signor Developer role - we have to think how to make it possible to have a developer role that can be controlled by a Signor Developer role, while still allowing for autonomy in the development process. This will require careful consideration of the architecture and design of the Weave project, as well as the implementation of appropriate access controls and permissions.
