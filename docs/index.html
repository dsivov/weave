Weave

A multi-user, multi-role system for running an AI development team: humans and autonomous agents planning, building and reviewing on one governed graph.

Built docs-first — vision, then proposal and requirements, then a binding architecture contract, then a plan whose milestones each pass a test gate before the next begins. Seven phases, seven milestones, every gate reproduced by a reviewer rather than accepted on report.

The written record

These are Markdown and render on GitHub rather than here — they are the working documents, not the presentation layer.

  • CONSTRAINTS.md — the architecture contract: 15 falsifiable sentences, non-goals, tripwires and an amendment log. v4, in force. Drift from it stops the build.
  • WEAVE_DRP.md — 64 numbered requirements, 7 flagged assumptions and how each gets verified, 43 acceptance criteria grouped by milestone.
  • WEAVE_WORK_PLAN.md — phases P0–P6 to milestones M0–M6, each with an explicit test gate. The checkboxes are the progress trace.
  • DECISIONS.md — every non-trivial choice and reversal, D-001 to D-035, with the reasoning that produced it.
  • DEMO_SCENARIO.md — the demo tenant: Weave's own build history, recorded in Weave, with every locator resolving to a real file.
  • Milestone reviews — M0 · M1 · M2 · M3 · M4 · M5 · M6 — each with a verdict per constraint and the gate reproduced independently.
  • DOCS_INDEX.md — the full map of docs/.

Checks run locally, not in CI (D-036). This repository publishes documentation only; its GitHub Actions workflow was removed. The name-guard, the Python suite and the UI build are run by hand before a commit — see D-036 for what that trades away and why.
